LICENSE CONTROL — CONTRATO FINAL DE LICENCIAMIENTO V3

MODELO
systems es el catálogo maestro. WEB usa users, user_system_access y roles/permisos
opcionales. WEB no requiere licencias de dispositivos.
ANDROID: systems -> system_licensing -> licenses -> license_devices -> licensed_devices.
system_licensing es opcional para el sistema y solo admite ANDROID.
Contiene Id_System, Licensing_Mode, Package_Name, Offline_Validity_Days (1..365),
Is_Active, Created_At, Modified_At.
licenses es la única entidad comercial: modalidad, propietario, vigencia y seats.
DEVICE_ONLY exige cliente; Id_User es NULL. USER_DEVICE exige usuario; cliente opcional.
No hay una entidad separada para asignar la licencia a un usuario.

ADMINISTRACIÓN
POST /api/admin/licenses {Id_System,Id_Customer?,Id_User?,Term_Type,Seat_Count}
La modalidad se obtiene de system_licensing; no la decide el cliente.
MONTHLY/ANNUAL/PERPETUAL: el servidor calcula Activated_At en UTC y Expires_At
a un mes/año calendario, o NULL. No se aceptan fechas de vigencia manuales.
GET /api/admin/licenses e /api/admin/licenses/{id}: propietario, sistema,
Effective_Status, Used_Seats, Available_Seats y detalle de dispositivos.
GET /api/admin/licenses?Id_User={id} filtra licencias del usuario.
POST /api/admin/licenses/{id}/status {status:ACTIVE|SUSPENDED|REVOKED}
REVOKED es terminal. EXPIRED se deriva de Expires_At; nunca se almacena como Status.
Una suspensión conserva seats; revocar revoca vínculos activos/suspendidos.
POST /api/admin/licenses/{id}/devices {deviceId}: solo USER_DEVICE.
Vincula un dispositivo ya registrado y activo, con bloqueo y control de seats.
No registra dispositivos manualmente ni genera códigos USER_DEVICE.
POST /api/admin/devices/{id}/retire {reason:LOST|REPLACED|REVOKED}
Retira el dispositivo y sus vínculos, conserva historial y libera seats.
Seats usados: license_devices.Status IN ('ACTIVE','SUSPENDED').
REVOKED, LOST y REPLACED no consumen seats.

CÓDIGOS DEVICE_ONLY
POST /api/admin/enrollment-codes {licenseId,expiresAt,sendEmail?}
expiresAt ISO UTC futuro, máximo siete días; distinto del vencimiento comercial.
Solo licenses DEVICE_ONLY activas y vigentes.
Código aleatorio de 256 bits, mostrado una vez; se guarda únicamente su SHA-256.
device_enrollment_codes: Id_Enrollment,Id_License,Id_Device NULL,Code_Hash,
Expires_At,Used_At,Created_At,Created_By.
No requiere dispositivo previo y no consume/reserva seats al generarlo.
sendEmail mantiene el envío al correo configurado del cliente después del commit.
Si SMTP falla, se devuelven los códigos creados y emailSent=false; no se regeneran.
GET /api/admin/enrollment-codes no expone códigos ni hashes.

ENROLLMENT
POST /api/mobile/device/enroll
{system,packageName,code,publicKey,fingerprint,signature,
 displayName?,manufacturer?,model?,androidVersion?,appVersion?}
system es systems.Code; packageName debe coincidir con system_licensing.Package_Name.
La clave privada EC P-256 no exportable se genera en Android Keystore.
publicKey: X.509 SPKI en Base64 estándar o PEM.
fingerprint: SHA-256 DER SPKI, hexadecimal lowercase.
signature: SHA256withECDSA, DER Base64 estándar, sobre UTF-8:
LC-ENROLL-V1\n{system}\n{packageName}\n{code}\n{fingerprint}
Separadores LF reales; sin LF final. El código no se transforma.
El servidor busca Code_Hash, obtiene Id_License, bloquea la licencia FOR UPDATE,
valida estado/vigencia/sistema/modalidad y vuelve a leer el código bajo bloqueo.
Cuenta vínculos ACTIVE/SUSPENDED con lectura bloqueante y valida Seat_Count.
Verifica posesión de clave, registra el dispositivo o reutiliza su identidad activa
por fingerprint, sin sobrescribir la clave ni rehabilitar dispositivos retirados.
Inserta license_devices ACTIVE, vincula Id_Device al código y marca Used_At.
Emite la credencial dentro de la misma transacción. Todo se revierte si falla.
No crea una segunda licencia. No requiere usuario, roles, sesión ni JWT web.

CHALLENGE / VERIFY / REFRESH
POST /api/mobile/device/{deviceId}/challenge {licenseId}
Respuesta: challengeId,nonce,expiresAt,deviceId,licenseId.
device_challenges usa Id_Challenge,Id_Device,Nonce,Expires_At,Used_At,Created_At.
Nonce Base64URL de bytes con contexto de licencia y aleatoriedad de 256 bits.
Expira en 120 segundos; máximo diez challenges/dispositivo/minuto.
Firmar bytes decodificados del nonce mediante SHA256withECDSA.
POST /api/mobile/device/{deviceId}/verify
POST /api/mobile/device/{deviceId}/validate
POST /api/mobile/device/{deviceId}/refresh
Body: {licenseId,challengeId,signature}; firma DER en Base64 estándar.
Cada llamada requiere challenge nuevo, de un solo uso y de la misma licencia.
Valida licenses, license_devices, licensed_devices y sistema antes de emitir.
No acepta vínculos suspendidos, revocados, perdidos ni reemplazados.

CREDENCIAL OFFLINE V3
JWS compacto ES256, typ=LC-OFFLINE-LICENSE, kid externo.
Firma de 64 bytes r||s (P1363), distinta del DER de las pruebas.
Payload:
formatVersion=3,licenseId,systemId,deviceId,packageName,fingerprint,
issuedAt,expiresAt,offlineUntil,status=ACTIVE.
Únicos IDs: licenseId,systemId,deviceId.
Tiempos epoch UTC segundos; expiresAt NULL en PERPETUAL.
offlineUntil=min(expiresAt,issuedAt+Offline_Validity_Days), o solo la ventana
offline para PERPETUAL. Respuesta: mismos campos, allowed=true, credential,serverTime.
El cliente debe fijar clave/kid/alg/typ y comprobar firma, versión, identidad,
paquete, fingerprint, estado y vigencias con tiempo confiable/monotónico.
Una respuesta negativa invalida el uso offline. Una desconexión real permite
usar solo una credencial firmada aún vigente. Revocar requiere conectividad
para ser conocido antes del vencimiento de la ventana.
Este contrato requiere actualizar posteriormente la APK; no se modificó aquí.

ERRORES FUNCIONALES
HTTP 403 {allowed:false,code,message}:
LICENSE_NOT_FOUND,LICENSE_SUSPENDED,LICENSE_REVOKED,LICENSE_EXPIRED,
NO_SEATS_AVAILABLE,DEVICE_REVOKED,ENROLLMENT_CODE_INVALID,
ENROLLMENT_CODE_EXPIRED,ENROLLMENT_CODE_USED,CHALLENGE_INVALID,CHALLENGE_EXPIRED.
ACCESS_DENIED para prueba de identidad/modalidad no autorizada.
429 para límite de challenges; 503 CREDENTIAL_UNAVAILABLE si no puede firmarse.
No confundir respuestas HTTP negativas con falta de conectividad.

EVENTOS
license_validation_events:
Id_Validation_Event UUID,Id_License,Id_Device,Id_System,Event_Type,
Success,Failure_Code,Created_At.
Los rechazos se registran fuera de la transacción revertida, sin secretos.

VERSIONES Y DESCARGAS
POST /api/admin/systems/{systemId}/versions, multipart APK y metadatos.
application_versions usa Id_System y las columnas del esquema final:
Id_Version,Version_Name,Original_File_Name,Storage_File_Name,Sha256,File_Size,
Minimum_Android,Release_Notes,Mandatory,Published,Is_Active,
Created_At,Created_By,Modified_At,Modified_By.
/api/portal/apps, /apps/{id}, /apps/{id}/versions y /downloads/{versionId}
usan systems y application_versions.Id_System, con user_system_access activo
para autorizar la distribución; no consumen seats ni registran dispositivos.
No se modificó el frontend Suite.

FIRMA
LICENSE_CONTROL_OFFLINE_PRIVATE_KEY_PATH: PEM PKCS#8 EC P-256 externo.
Alternativa: LICENSING_SIGNING_PRIVATE_KEY. El archivo tiene prioridad.
LICENSE_CONTROL_OFFLINE_KEY_ID configura kid.
Solo distribuir la clave pública; HTTPS obligatorio.
No se ejecutó el script de reset ni se modificó la base de datos en esta tarea.
